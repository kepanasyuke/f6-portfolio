# 08 · Data Portal

Корпоративный обозреватель данных стенда: все базы сервисов в одном окне.

- **Только чтение.** Подключение через `file:…?mode=ro`, портал не меняет данные.
- **Сводка.** Восемь KPI считаются SQL-запросами по базам: индикаторы, детекции, журналы, узлы и связи графа, домены под риском, отчёты, проблемы хостов.
- **Дерево источников.** Реестр из семи баз: таблицы, число строк, доступность файла.
- **Таблица данных.** Поиск по всем текстовым колонкам (`LIKE` по каждому полю), сортировка по клику на заголовок, пагинация, схема колонок, выгрузка CSV с `;` для Excel.

## Почему порт 8109

Порт 8108 на этой машине занимает сторонний процесс (`tools\screenshots.py`), поэтому сервис поднят на 8109.

## API

| Метод | Путь | Смысл |
| --- | --- | --- |
| GET | `/api/summary` | KPI + источники с таблицами |
| GET | `/api/sources` | только дерево источников |
| GET | `/api/rows?source=&table=&limit=&offset=&sort=&direction=&q=` | страница данных |
| GET | `/api/export.csv?source=&table=&q=` | выгрузка до 200 строк |

Имена таблиц проверяются по `sqlite_master`: посторонние (`sqlite_master`, `sqlite_sequence`) дают 404, идентификаторы экранируются.

## Запуск и тесты

```powershell
.\run.ps1                                  # http://127.0.0.1:8109
..\.venv\Scripts\python.exe -m pytest . -q
```

Тесты поднимают временный корень данных (`F6_DATA_ROOT`) с двумя базами и проверяют реестр, пагинацию, поиск, сортировку, отказ на 404 и CSV.
